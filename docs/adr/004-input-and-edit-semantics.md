# ADR-004：交互输入与受控编辑的运行语义

**状态：** 已采纳（R0）
**依据：** 设计文档 §6.6/§6.7/§19.6（验收 A19—A22）

## 决策

1. **用户先发送，运行才开始**：打开课程/会话只创建 `sessions` 行（冻结课程版本、代码版本、模型快照、资产与预算快照），不创建运行、不调用模型；案例提示只能插入输入框草稿，插入动作无任何网络副作用（E2E 覆盖）。
2. **幂等队列**：`(session_id, client_message_id)` 唯一——同键同文返回既有记录（200/duplicate），同键异文 409；撤回仅对 queued 生效；替换 = 原子 replaced + 新 ID。
3. **接纳与冻结**：普通输入只在该会话无活动 run 时接纳；接纳时冻结"已接纳会话前缀"为 `conversation_snapshot_id`，后续运行将其作为候选上下文（且只读取已接纳部分，绝不读未来排队消息）。
4. **版本绑定在提交时刻**：`input_submissions.agent_revision_id` 在提交时从用户选择冻结；排队后修改会话默认版本不影响已排队输入（协调器从输入行读取版本）。
5. **控制语义**：暂停 = 下一个安全边界驻留等待（不给网络调用中的模型发 pause）；取消 = 尽快终止并落入 `cancelled` 终态；撤销输入 ≠ 取消已接纳运行（两者分离的 API）。

## 证据

- `tests/e2e/api-flow.spec.ts`（A19/A21）、`tests/fault/cancel-and-queue.spec.ts`、`packages/conversation` 单元/集成覆盖。
